# Open Question Register

**Status:** Current as of Phase 1 PR 2 (identity and organization foundation), 2026-08-04
**Companion to:** `docs/governance/RISK_REGISTER.md`. A risk is something that could go wrong; an
open question is something not yet decided or not yet supplied. They are tracked separately so
that "we have not decided" is never filed as "we have mitigated".

Reviewed at every phase exit gate.

## Status legend

- **Resolved** — an owner ruling or artifact answers it. Kept for traceability.
- **Open, non-blocking** — Phase 1 proceeds; the answer changes a later phase or a tenant's
  behaviour, not the build.
- **Open, blocking** — named work cannot start or merge until answered.

### OQ-19 — Kill-switch scope expansion

> **RESOLVED in Phase 1 PR 2.** Migrations `0014_kill_switch_scope_values` (declaring
> `-- freightos:no-transaction`) and `0015_kill_switch_scope_expansion` add both values, extend the
> scope-reference and tenant-shape constraints, extend the read/write/release policies, and replace
> `app.resolve_kill_switch_mode` with an eight-parameter form whose first six positions are
> unchanged. `KILL_SWITCH_SCOPES` and `ResolutionRequest` in `packages/context/src/kill-switch.ts`
> mirror it. `0016_autonomous_mobility_standing_suspension` seeds the ADR-0019 standing suspension.
>
> Evidence: `packages/database/test/integration/kill-switch-scopes.test.ts` — 28 assertions,
> including a regression that captures resolution for a matrix of Phase 0 records with both
> migrations reverted and replays it after, asserting identity; and
> `packages/context/test/unit/kill-switch.test.ts` — 22 assertions.
>
> Beyond the specification: `released_by_type` was added, because the required test "agent or model
> actors cannot engage **or release** a kill switch" was unenforceable while `released_by` was an
> unconstrained text column. Art. V.1 reserves both acts to humans; Phase 0 constrained only one.

### OQ-20 — Purpose and outcome fields

> **RESOLVED in Phase 1 PR 2.** Migration `0006_audit_purpose_and_outcome` adds `purpose`,
> `outcome` and `operation_class` to `audit_events` and a mandatory `purpose` to `outbox_events`,
> and lands **before** `0013_control_plane_admin` creates the `admin` schema — so no `admin.*`
> function ever shipped without the columns to record it. `schemas/event-envelope.schema.json`
> gains a required `purpose` attribute as a declared override.
>
> **Three declared overrides, not four.** The specification anticipated a new override entry;
> `schemas/event-envelope.schema.json` already had one from ADR-0015, so the `purpose` addition
> extends it — its `adr` field now reads `ADR-0015,ADR-0019` — and the count stays at 3. The
> obligation is met; the arithmetic in the original text assumed a file with no prior override.
>
> Evidence: `packages/database/test/integration/control-plane.test.ts` — 47 assertions covering
> missing actor, missing purpose, purpose outside the vocabulary, agent actor, missing tenant scope,
> missing correlation id, and append-only enforcement after the widening;
> `packages/identity/test/unit/purpose.test.ts` — 33 assertions including the trust boundary; and
> `packages/schemas/test/unit/schemas.test.ts` — envelope validation with and without `purpose`.
>
> Two implementation points a reviewer should see, both in
> `adr/0026-identity-implementation-decisions.md`: a privileged **denial returns** rather than
> raising, because a raise would roll back the audit row ADR-0020 requires; and a denied privileged
> row is exempt from the purpose requirement, because the commonest reason to deny is that no valid
> purpose was supplied and inventing one is exactly what OQ-20 forbids.

| Field                           | Value                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Deficiency**                  | Event envelopes lack a required `purpose`; `schemas/event-envelope.schema.json` sets `additionalProperties: false`, so an envelope carrying one is currently invalid. `audit_events` (`0003_audit_and_outbox.up.sql:15-44`) has neither `purpose` nor `outcome`, both mandatory under Ruling D                                                                                                                                       |

Nothing defers to PR 6                                                                              |
| **Blocking dependency**         | Blocks the ADR-0020 privileged-access audit requirement. No `admin.*` function may ship before the columns exist to record its purpose and outcome                                                                                                                                                                                                                                                                                   |
| **Required migration**          | Add `purpose text` and `outcome text` to `audit_events`. `outcome` is a closed set — `CHECK (outcome IN ('succeeded','denied','failed'))`. `purpose` is `NOT NULL` for privileged control-plane operations, enforced by a CHECK conditioned on the operation class rather than made globally mandatory, so Phase 0 rows stay valid                                                                                                   |
| **Required schema work**        | Add `purpose` to `schemas/event-envelope.schema.json` as a required context attribute. ### OQ-21 — Custody-event authority model drift

| Field                            | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Deficiency**                   | `schemas/custody-event.schema.json` retains the obsolete overloaded `authority_mode` concept with its five pre-ADR-0015 values. It does not reflect ADR-0015 or Ruling A, and it is a verbatim handoff copy with **no declared override**, so a Phase 1 custody event cannot express the two-dimension legal model                                                                                                                                                                                                                          |
| **Target PR**                    | **PR 6** — the expected target. Dependency analysis: the exception "unless custody contracts are required earlier by PR 5" **does not apply**. The approved data model (`docs/plans/…` §7) allocates `custody_events` to **PR 7**, not PR 5, and PR 5's freight-core table set does not include it. PR 6 is "State machines, event contracts, and lifecycle enforcement" — the custody event contract is an event contract, and defining it in PR 6 puts the contract one PR ahead of the table that uses it, which is the correct ordering |
| **Blocking dependency**          | Blocks **PR 7**, where `custody_events` is created. No custody event may be written against a schema that contradicts the binding legal model. PR 6 must land the corrected contract before PR 7 creates the table                                                                                                                                                                                                                                                                                                                          |
| **Required schema work**         | Replace `authority_mode` with **`legal_authority_class`** and **`operating_context`**, mirroring `schemas/event-envelope.schema.json`: the same enum values, the same ADR-0015 rule-6 pairing constraint expressed as a `oneOf`, and `legal_entity_id` required except under system scope. Declare the file as an authorized `override` in `handoff-provenance.json` citing ADR-0015 and ADR-0019                                                                                                                                           |
| **Compatibility and versioning** | The schema is versioned. The replacement is a **breaking change** to the custody contract and takes a new major version; the prior version is retained as the historical contract. The total, lossless mapping in ADR-0015 §"Migration from `authority_mode`" is the documented conversion, and `fromAuthorityMode()` in `packages/context/src/legal.ts:150-168` is its implementation                                                                                                                                                      |
| **No silent mutation**           | **Existing events must not be silently mutated.** No custody event exists today, so nothing is rewritten in practice — and the rule is recorded because it binds any future contract change. A stored event keeps the schema version it was written against; re-interpretation under a newer version is a new record, never an edit                                                                                                                                                                                                         |
| **Required migration**           | None in PR 6. This is a schema and provenance change only. The `custody_events` table itself is authored fresh in PR 7 under the two-dimension model                                                                                                                                                                                                                                                                                                                                                                                        |
| **Required tests**               | Schema validation accepts a valid two-dimension custody event; **negative tests** reject an event carrying `authority_mode`, reject an impermissible class/context pairing, reject a missing `legal_entity_id` outside system scope, reject a missing evidence array (`minItems: 1`), and reject an unknown enum value; provenance check passes with the new declared override                                                                                                                                                              |
| **Exit evidence**                | `PROVENANCE=PASS` with the declared override and its ADR citation; schema-validation output for accepted and rejected fixtures; 90/90 handoff checksums still passing, proving the preserved source was not edited                                                                                                                                                                                                                                                                                                                          |
| **Owner input still required?**  | **No.** ADR-0015 and Ruling A settle the model, and the dependency analysis lands on the expected target PR 6                                                                                                                                                                                                                                                                                                                                                                                                                               |
