## Discovered security findings

Findings uncovered by review or forensic analysis rather than anticipated as risks. A risk is
something that could go wrong; a finding is something that already was wrong. They are recorded
separately so that "we found and fixed this" is never filed as "we foresaw this".

### SR-AUDIT-ACL-NOOP — `app.record_audit_event` executable by PUBLIC

| Field                 | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Severity**          | High                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Status**            | **Closed** — migration `0031_audit_function_acl_hardening`                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Discovered**        | During the N5-A disclosure-architecture closure, while verifying whether N5 could couple grant writes to the existing audit path without adding a `SECURITY DEFINER`. Not found by any gate.                                                                                                                                                                                                                                                                                                                                  |
| **Affected object**   | `app.record_audit_event(text,text,text,uuid,uuid,text,jsonb)` — `SECURITY DEFINER`, owned by `freightos_audit_writer`, which is one of only three roles holding `INSERT` on `audit_events`                                                                                                                                                                                                                                                                                                                                    |
| **Root cause**        | Migration `0018` §1 issued `REVOKE ALL … FROM PUBLIC` and `GRANT EXECUTE … TO freightos_app` at lines 207–210, **after** the `RESET ROLE` on line 205. Execution had returned to `freightos_migrator`, which administers the owner `WITH SET TRUE, INHERIT FALSE`; without `INHERIT`, PostgreSQL does not treat it as the owner and discarded both statements with `WARNING`, not `ERROR`. The migration driver does not promote warnings, so `0018` recorded as applied and the function kept its creation-time default ACL. |
| **Impact**            | Audit-ledger forgery. `payload.provenance` still recorded the true PostgreSQL principal, so forged rows were detectable — but Constitution Art. II.1 makes the ledger authoritative, and an authoritative record an unrelated service can write false entries into is not authoritative.                                                                                                                                                                                                                                      |
| **Exploit roles**     | Any role that can log in and is not `freightos_app`: `freightos_event_writer`, `freightos_control_plane`, `freightos_admin`, `freightos_migrator`. Because `session_user` is not `freightos_app`, `app.current_tenant_id()` and `app.current_actor_id()` use their legacy GUC branch, so the caller supplies both. **Reproduced** with `freightos_event_writer`, which inserted a row naming a tenant of its choosing and a fabricated `human` actor. Rolled back.                                                            |
| **Not affected**      | Cross-tenant reads (the exploit roles cannot `SELECT audit_events`), the append-only triggers, the table ACL, RLS, and every N1–N4 network object.                                                                                                                                                                                                                                                                                                                                                                            |
| **Remediation**       | `0031_audit_function_acl_hardening` applies the ACL under `SET LOCAL ROLE freightos_audit_writer` — the identity PostgreSQL accepts — then asserts the result from `pg_proc.proacl`. Converges fresh clusters and clusters carrying the broken ACL alike. `0018` is applied history and is not edited.                                                                                                                                                                                                                        |
| **Authorized caller** | `freightos_app` only, established by inventory: no function body calls it, no runtime TypeScript calls it, and both integration call sites connect as `freightos_app`. `freightos_control_plane` was named by `0018`'s never-effective `GRANT` and is deliberately not restored.                                                                                                                                                                                                                                              |
| **Regression gate**   | `audit-function-acl.test.ts` pins the explicit grantee set (not mere reachability, which passed against the defect), the negative role matrix including an operator LOGIN, the exploit itself, and the role graph. `audit-acl-migration.test.ts` proves the upgrade path from a genuinely broken `0030` database on a private cluster. Mutations M-A…M-E each fail for their intended detector.                                                                                                                               |
| **Class regression**  | The generalisable lesson is that an ACL statement can succeed as SQL and change nothing. `0031` §3 reads the catalog back rather than trusting execution, and `audit-function-acl.test.ts` asserts from the migration source that it still does — including that `RESET ROLE` follows the ACL statements rather than preceding them.                                                                                                                                                                                          |
| **Down semantics**    | Deliberately asymmetric: reverting `0031` does **not** restore `PUBLIC EXECUTE`. See `0031_audit_function_acl_hardening.down.sql`, and the narrowed comparison in `migration-path-parity.test.ts`.                                                                                                                                                                                                                                                                                                                            |
| **Owner**             | Engineering                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
