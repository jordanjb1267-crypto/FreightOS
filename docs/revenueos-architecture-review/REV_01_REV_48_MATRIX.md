## Scoring rules

Documentation presence is never PASS. Design intent is never PASS. A schema alone is never a
runtime PASS. An unmerged branch is never PASS. **FAIL** is reserved for cases where an artifact or
control _contradicts_ the gate; where the capability simply does not exist, the score is
**NOT_IMPLEMENTED**.

Several gates are **vacuously safe**: the attack they prevent is impossible today because the
subject does not exist (no seller, no sale, no egress, no payment rail). These score
NOT_IMPLEMENTED or PARTIAL, never PASS, and are marked _vacuous_ so the distinction survives.
