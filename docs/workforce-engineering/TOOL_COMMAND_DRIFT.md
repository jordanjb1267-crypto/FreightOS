## Method and the operative rule

Sources: `matrices/tool_command_matrix.csv` and the Job Book JSON `tools`/`commands`/`non_scope` (design); `config/agents/registry.yaml` `allowed_tools`/`prohibited_actions` (declared); `config/policy/base_policy.yaml` `red_actions` (32 items, read by nothing — W0 §4); `packages/identity/src/permissions.ts` `PHASE_1_PERMISSIONS` (22 identity-plane strings); `scripts/validate-scope.mjs:464-468` (any non-empty `allowed_tools` fails CI: "no tool registry exists yet").

**Operative rule (C-9):** `allowed_tools: []` on all 32 manifests means **no tool may be called**; the tools and commands named in Job Books are Phase-2 design input, not an allowlist. No tool registry, per-tool schema, command handler, or canonical action vocabulary exists (`POLICY_REGISTRY.md` gap 7; OQ-16 open).

Drift types: `PLACEHOLDER_COMMAND` (`*_typed_command`), `GENERIC_TOOLS` (all tools template-generic — global or department-wide), `NO_MANIFEST`, `MANIFEST_NO_JOB`, `PROHIBITED_LIST_NOT_IN_JOBBOOK` (a registry prohibited action with no counterpart in the book's non-scope), `TOOL_NAMED_NO_REGISTRY` (a Job Book names tools while no registry exists), `COMMAND_NOT_IN_POLICY_VOCAB` (no Job Book command appears in `red_actions` or `PHASE_1_PERMISSIONS`).

## Placeholder commands (40 jobs)

Every facility (18), shipper (12) and service-provider (10) book declares exactly one command — `facility_typed_command`, `shipper_typed_command`, `service_provider_typed_command`. WF-08 ("every consequential command is enumerated") is unmet at design level for these 40 jobs; **Finding W01-F-TOOL-01.**

## Generic tool sets (40 jobs)

Facility: `tenant-scoped read model, FOT retrieval, policy query, FacilityOS domain services, evidence retrieval, approved communications gateway`; Shipper: the same with `SOT retrieval`/`shipper domain services`; Service Provider: `SPOT/RigDesk retrieval`/`provider domain services`. None names an adapter, engine or system a job would actually call. **Finding W01-F-TOOL-02.**

## Vocabulary collisions and gaps

- Job Book commands (e.g. `assign_driver_equipment`, `send_dispatch_instruction`, `open_exception`, `create_carrier_payable`, `record_allocation_proposal`) use `verb_object` snake case; `base_policy.yaml` red actions use `object.verb` (`contract.amend`, `money.move`); registry prohibited actions use the same dotted form; `PHASE_1_PERMISSIONS` use `identity.*`/`governance.*`. Three vocabularies, no canonical registry — the known collisions of `POLICY_REGISTRY.md` gap 7 (`contract.amend` vs `contract.materially_amend`; `policy.change` vs `autonomy_policy.change`) remain and are joined by 91 new unmapped strings. OQ-16 open. **Finding W01-F-TOOL-03.**
- Registry `prohibited_actions` are not reproduced in the matched Job Books for 19 of 24 matched jobs (e.g. `tracking-agent: milestone.fabricate`, `documentation-agent: document.forge`, `gate-agent: credential.security_override`); the union of both lists is the operative prohibition set (C-5). **Finding W01-F-TOOL-04.**
- Brokerage `carrier_pay` names `payment-status adapter` and `money engine`; v1.6 Art. III makes payment destination and invoice math red for models — the tool must be a deterministic service behind a human-approved change control, which the book does not state.

## What a tool registry would need (requirements only — no implementation proposed here)

A canonical action vocabulary shared by policy, permissions, registry and Job Books (OQ-16); per-tool parameter/return JSON Schemas; per-job allowlists derived from Job Books and validated in CI against the registry (WF-37); the empty-allowlist invariant retained until each tool has a schema and an owner; prohibited-action union enforced at the command boundary (ADR-0004: agents act only through typed commands); no free-form shell/database tools (v1.3 `12_…:58-64`).
