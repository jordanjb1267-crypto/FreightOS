**Status:** W0/W1 audit deliverable — a scoring of the v1.8 gates against repository evidence at `main` @ `09624b9`, not a certification of anything. **Branch:** `audit/v1.8.0-workforce-w0-w1`. **Date:** 2026-08-15. **Companions:** every other file in this directory; the evidence for each cell is in [`CURRENT_WORKFORCE_INVENTORY.md`](CURRENT_WORKFORCE_INVENTORY.md) (W0 §n references) and the W1 matrices.

> A gate cannot be PASS when evidence exists only in an unmerged branch, mock, or document. — v1.4.0 `24_ACCEPTANCE_GATES_EVIDENCE_MATRIX.md`

Gate text is quoted verbatim from `docs/production-handoff/v1.8.0-agent-workforce-engineering-certification/12_WORKFORCE_ACCEPTANCE_GATES.md`, which also states the two blocking clauses applied at the end of this file. v1.8 defines no status vocabulary; the owner-instructed vocabulary is used, and where v1.8 is silent the strictest neighbour applies (v1.4's rule above; v1.5 "FAIL blocks production autonomy in affected scope").

## Legend (declared before scoring)

| Status                 | Meaning here                                                                                                                                                                                                                                                    |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **PASS**               | code, test or CI evidence at `09624b9` satisfies the gate for every in-horizon subject                                                                                                                                                                          |
| **PARTIAL**            | a real, tested repository mechanism enforces part of the gate (which part is stated), **or** the mechanism exists at platform level but no job yet exists to be governed by it (stated explicitly). A design artifact alone is never PARTIAL                    |
| **FAIL**               | no repository evidence, or the design artifact itself is incomplete for in-horizon subjects                                                                                                                                                                     |
| **NOT YET APPLICABLE** | the gate's only subjects are promotion/legal/customer-gated modules or an unreleased artifact (module state cited); where a gate has an in-horizon design component it is scored, and NOT YET APPLICABLE is never used to avoid a FAIL on an in-horizon subject |

(The v1.3 audit in `docs/security-resilience/` used `NOT IMPLEMENTED` as its fourth value; this file uses the owner-instructed `NOT YET APPLICABLE`, which has a narrower meaning — do not conflate them.)
