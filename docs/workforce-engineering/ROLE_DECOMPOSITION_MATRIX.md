# Role Decomposition Matrix — v1.8.0 W1

**Status:** W1 audit deliverable — a decomposition verdict per role, not an implementation claim. **Baseline:** `main` @ `09624b9`. **Branch:** `audit/v1.8.0-workforce-w0-w1`. **Date:** 2026-08-15. **Companions:** [`CURRENT_WORKFORCE_INVENTORY.md`](CURRENT_WORKFORCE_INVENTORY.md) (W0 evidence), [`JOB_BOOK_IMPLEMENTATION_MATRIX.md`](JOB_BOOK_IMPLEMENTATION_MATRIX.md) (design × implementation per job).

> A gate cannot be PASS when evidence exists only in an unmerged branch, mock, or document. — v1.4.0 `24_ACCEPTANCE_GATES_EVIDENCE_MATRIX.md`

## Method

**Input universe.** (a) the 32 manifests in `config/agents/registry.yaml` (declared only); (b) the 76 v1.8 Job Books (design only); (c) every code component that behaves like a worker, service, policy function or human approval role (the W0 inventory §§3, 4, 12, 13, 15, 16, 18, 19). Where a manifest and a Job Book are the same role they share one row (24 such rows); the 7 autonomous-mobility manifests with no Job Book and the 16 code-only platform components have their own rows. Total rows: 76 + 7 + 16 = 99.

**Classification** — exactly one of `KEEP_AGENT | HYBRID_AGENT | DETERMINISTIC_SERVICE | WORKFLOW_SERVICE | MERGE_WITH_EXISTING_JOB | HUMAN_ONLY | MISSING_IMPLEMENTATION | NOT_IN_CURRENT_HORIZON` per row, decided by:

1. **Module state first** (`config/scope/module_states.yaml`, pinned by `scripts/validate-scope.mjs:42-61`): a job whose module is not `ACTIVE_BUILD`/`FOUNDATION_ONLY` is `NOT_IN_CURRENT_HORIZON`; its decomposition verdict is still recorded in the **Would-be class** column so W3+ can reuse the analysis and so WF-04/WF-05 can be judged on the design.
2. **Autonomy** = min(v1.8 §18 statement, registry declared, module ceiling, Horizon-1 A3 cap) via `effectiveMaximumAutonomy()` (`packages/config/src/autonomy.ts:72`); Phase 1 additionally ≤A2 (`docs/decisions/0002` §8). No declared A4 is ever reported as allowed.
3. **The five anti-sprawl questions** of v1.8 `00_MASTER_WORKFORCE_HANDOFF.md` (Q1 recurring contextual judgment · Q2 adaptive communication/planning · Q3 multiple tools/sources · Q4 one bounded owned outcome · Q5 evaluable as a job) — a role keeps an LLM only when the answers are all "yes"; arithmetic, eligibility rules, exact clocks, schema validation, authorization, idempotency, fixed routing and state transitions stay deterministic (v1.8 `01_ROLE_DECOMPOSITION…`).
4. **Merge** when a job's owned outcome is already owned by another job or manifest, or when two jobs could both believe they own the same WorkUnit (v1.8 `03_…` "No orphan work", one accountable owner).
5. **Human only** where the outcome is a red action or a legal/safety/compliance clearance (v1.2 `09_…:9-21`; v1.6 Art. III/X; v1.8 `05_…` "no high-risk hold closes from model confidence alone").
6. Physical-motion, PLC, barrier, dock-restraint, door, yard-vehicle, conveyor, robotics and safety-interlock authority is never a classification outcome; it is preserved verbatim as prohibited (v1.2 `09_…:49-53`; `validate-scope.mjs:481-494`; migration 0016; `capabilities.ts:140-153`).
7. Brokerage rows carry "separate legal plane; no activation"; service-provider rows carry "RigDesk is system of record (Ruling C, OQ-3)"; shipper rows preserve legal routing (Ruling A).

**`MISSING_IMPLEMENTATION`.** Every in-horizon row (the 14 carrier jobs, module `carrier_copilot`/`rigdesk_maintenance_hooks` ACTIVE_BUILD) has **no code at all**; the decomposition verdict is kept in the Classification column so the audit answers "agent or not?", and the row carries the flag `MISSING_IMPLEMENTATION` in its evidence cell and `IMPLEMENTATION_ABSENT` in the companion matrix. Nothing in the repository implements any of the 76 jobs (W0 §§1–19).

**Stricter-rule overlaps applied** (the fourteen that mattered, from the controlling-architecture reading): C-1 computed autonomy minimum (ADR-0018 — never read `maximum_autonomy` directly); C-2 v1.2 `09_…` absolute physical-control wording over FacilityOS Art. I; C-3 brokerage dormancy and the registry generator's deletion of brokerage-plane variants (never resurrected); C-4 v1.8 `deterministic_service` beats registry A1 for the five engines; C-5 registry `prohibited_actions` ∪ Job Book `non_scope`, never one replacing the other; C-6 J-level ∧ A-level conjunction, shadow before A3+; C-7 union of approval-binding fields, "material change invalidates" unqualified; C-8 8-level kill-switch union; C-9 empty `allowed_tools` is the operative grant — `tool_command_matrix.csv` is design input, not an allowlist; C-10 orchestrators are routing roles, never authority tiers; C-11 agent messages are never authority; C-12 v1.4 evidence rule governs all 237 gates; C-13 `acceptanceState`/`approvedBy` treated as required despite the shipped schemas; C-14 Twin `PROPOSED` facts cannot authorize.

**Evidence rule.** Handoff text is design evidence only; registry entries are declared only; every code citation was re-opened at HEAD (see the inventory's verification log). Highest truthful maturity for every v1.8 job is `DESIGNED` (or below it for the 41 design stubs); platform primitives may be `IMPLEMENTED`.
