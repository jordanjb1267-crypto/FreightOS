# Evaluation Gap Matrix — v1.8.0 W1

**Status:** W1 audit deliverable. **Baseline:** `main` @ `09624b9`. **Branch:** `audit/v1.8.0-workforce-w0-w1`. **Date:** 2026-08-15.

> A gate cannot be PASS when evidence exists only in an unmerged branch, mock, or document. — v1.4.0 `24_ACCEPTANCE_GATES_EVIDENCE_MATRIX.md`

## Method

v1.8 `06_JOB_CERTIFICATION_AND_EVALUATION.md` requires, per Job Book, thirteen case families — golden, ambiguous, missing/stale/conflicting data, permission denial, policy denial, prompt injection, duplicate/out-of-order event, tool failure, partial write, crash recovery, customer override, cross-tenant, high-risk escalation — and names seven **certification-blocking failures** regardless of aggregate score (unauthorized side effect; tenant/counterparty data leak; false legal/safety/compliance clearance; duplicate financial/booking effect; fabricated authoritative status; approval bypass; missed mandatory escalation). Certification ladder J0 SPECIFIED → J1 OFFLINE → J2 ADVERSARIAL → J3 REPLAY → J4 SHADOW → J5 A3 → J6 A4 → J7 A5.

Each Job Book's "Job-specific certification scenarios" section was scored per family: **SPEC** — a job-specific (non-template) line names it; **GEN** — only the template line names it; **NONE** — not named. Template = verbatim in ≥20 books or ≥90 % of the department.

**Repository evaluation infrastructure (W0 §17):** three Vitest projects, 85 test files, ~1,657 `it()` blocks — all platform primitives; coverage thresholds cover only `packages/identity/src/**` and `capabilities.ts`; no mutation testing; one fixture file; **`evals/` does not exist** although all 32 manifests point at `evals/<id>.eval.yaml`; no simulation harness; no `JobCertification` record, table or schema copy; OQ-15 (agent acceptance thresholds) open. No test anywhere references a v1.8 job.
