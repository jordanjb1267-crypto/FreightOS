# Proposed Additive PR Sequence — after W0/W1

**Status:** recommendation only. Nothing in this file is authorized by this file; W2 is **not** presumed to be next. **Baseline:** `main` @ `09624b9`. **Branch:** `audit/v1.8.0-workforce-w0-w1`. **Date:** 2026-08-15. **Companions:** [`WF_01_WF_40_MATRIX.md`](WF_01_WF_40_MATRIX.md), [`JOB_BOOK_IMPLEMENTATION_MATRIX.md`](JOB_BOOK_IMPLEMENTATION_MATRIX.md), [`OWNER_DECISIONS.md`](OWNER_DECISIONS.md).

> A gate cannot be PASS when evidence exists only in an unmerged branch, mock, or document. — v1.4.0 `24_ACCEPTANCE_GATES_EVIDENCE_MATRIX.md`

## Preamble — what governs this sequence

- **Module-state governance controls** (v1.8 `09_IMPLEMENTATION_SEQUENCE.md`: "This sequence does not override module-state governance"; `HORIZON_PROMOTION_GATE.md`: "A phase prompt, feature flag, schema, prototype, or successful simulation does not satisfy this gate by itself"). Nothing below promotes a module, raises an autonomy ceiling, signs a gate, activates brokerage, enables A3/A4/A5, runs a production migration, changes a permission, or performs a live external write.
- **Installed packages are immutable** (SR ruling 2; ADR-0014 §3) absent an explicitly approved corrective amendment (`docs/security-resilience/README.md` §A.4a items 1 and 5). Any Job Book, matrix, contract or simulation remediation is therefore recommended as a **new additive package** (v1.8.x or v1.9) rather than an edit of `docs/production-handoff/**`.
- **W2 is conditional on design.** W0/W1 confirmed material design incompleteness (41 design-stub Job Books, zero facility/shipper/service-provider edges, placeholder commands, generic tools and evaluations, seven simulation stubs, contract optionality, catalog/schema field drift, roster mismatch). Therefore a conditional **AWE-D1 Workforce Design Remediation** phase is inserted, and **no affected workforce may advance to runtime implementation until its design reaches the same required engineering depth** (all 18 attributes job-specific, typed edges registered, job-specific evaluations, runnable simulation specifications).
- **Nothing below starts without owner authorization** (v1.8 `10_…`; v1.2 `02_…`): each card names the approval it needs, and W0/W1 stops here.
- **Delivery spine unchanged** (SR ruling 1): the v1.2 ten-PR Phase 1 sequence remains the spine; the v1.3/v1.4 overlays remain mandatory; Phase 1 contains no agent runtime, tool invocation, scoring or negotiation (`docs/decisions/0002` §5). Everything below that touches carrier job logic is Phase 2+ work and must wait for its phase prompt.
- Card format follows `docs/security-resilience/PHASE_0_PR_PLAN.md`; IDs `AWE-n` (Agent Workforce Engineering) so they never collide with `WF-nn`, `SR-n`, `N-n`.
